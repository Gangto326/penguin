# Penguin 측정

Penguin은 공짜가 아니다. 이득(땜빵 루프 우회 절약)과 비용(흐름 중단, 시간,
오발동)이 반드시 함께 존재하므로, **양쪽을 같은 장부에 기록**한다.

## 트레이드오프 목록 (v1에서 인지하고 있는 비용)

| 비용 | 크기 (추정) | 측정 방법 |
|---|---|---|
| hook 오버헤드 | Edit/Write당 python 프로세스 1회, 수십 ms. LLM 호출 없음 — 사실상 무시 가능 | 체감 시 `time` 실측 |
| 발동 시 재검토 비용 | LLM 턴 1회분의 시간·토큰 (수십 초~수 분). **가장 큰 실비용** | 발동 로그에 대략 소요 기록 |
| 오발동 (정상 수렴 디버깅 중단) | 임계 4로 완화했으나 hook은 "보정"과 "정상 연속 편집"을 구분 못 함 | 발동 로그의 결과 분류에서 "현행 유지 확인" 비율 = 오발동률 근사 |
| 넛지 무시 | 모델이 안 따르면 주입된 컨텍스트만 오염 | 발동 로그의 "무시" 비율 |
| 갈아엎기 과잉 | 재검토가 rewrite를 과잉 처방할 위험 — SKILL.md 5단계의 "실측 근거 필수"가 안전핀 | 재설계 채택 건의 사후 평가 |

## 정직성 경계

절약된 시간은 **반사실적**이다 — 실사용에서 "Penguin이 X시간을 절약했다"는
수치를 지어내지 않는다. 그런 수치는 결말을 아는 과거 사례의 **백테스트**
(`results/`의 날짜별 문서)에서만 말할 수 있다. 실사용에서는 발동당 결과
분류만 기록한다.

## 기록 방법

발동(수동 `/penguin`, 넛지 경유, description 자동)마다 `results/log.md`에
한 행. 가볍게 — 한 줄이면 된다.
