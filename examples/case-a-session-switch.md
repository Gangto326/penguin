# 사례 A — 세션 전환 (땜빵 5겹 → 전면 재설계)

## Penguin 없이 (실제 역사, 2026-08-09~11)

래퍼가 TUI 입력창에 `/resume`을 대신 타이핑, 화면 패턴 감지 상태 머신으로
진행하는 구조에서:

1. `/back`이 유휴 상태에서 멈춤 → "타이머로 전진시키자" (패치 1)
2. 주입 텍스트가 사라짐 → "화면 상태 게이트를 달자" (패치 2)
3. 게이트도 타이밍을 못 잡음 → "재렌더 완료 플래그를 추가하자" (패치 3)
4. 그 신호가 재렌더에 아예 없음이 실측됨 → "재시작 방식과 혼합하자" (패치 4 설계)
5. 부팅 렌더에도 신호가 없음이 실측됨 — **감지 기반 기능 전부가 이미
   조용히 죽어 있었다.**

루프를 끊은 건 사용자의 질문("이 방향이 맞아? 강건하고 심플한 로직이
필요해")이었고, 재설계 결과 감지·상태 머신·타이핑 주입 전부 삭제(순
삭제 ~400줄), 전환은 "파일 쓰고 프로세스 갈아끼우기"로 환원됐다.
**우회 비용: 약 하루.**

## Penguin 있었다면 (패치 3 직전 발동 — 백테스트 실제 출력 발췌)

> **패치 계보**: 각 패치는 직전 패치가 깨뜨린 동기화를 다음 관측 신호로
> 다시 붙잡으려는 시도이고, 전제는 매번 "화면 출력 = 신뢰할 수 있는
> 동기화 지점"이라는 원설계 전제를 그대로 상속하고 있다.
>
> **전제 검증**: 원설계 전제 — *가정*. 측정 기록이 없다. 오히려 패치 1의
> 존재("유휴 상태에서는 감지 신호가 안 온다")가 이 전제의 첫 반례다. (…)
> 패치 3 전제 — *한 번도 실측되지 않은 가정.* **다음 패치보다 실측이
> 먼저다. 여기서 멈춘다.**
>
> **요구 분해**: ①안전한 종료 ②대상 세션으로 열기 ③컨텍스트 주입 — 셋 다
> MUST인데 현재 구조는 셋 전부를 휴리스틱으로 구현하고 있다.
>
> **수단 재탐색**: 세 MUST 전부에 문서화된 인터페이스(SIGTERM /
> `claude --resume` / UserPromptSubmit hook)가 존재하고 문서에 이미 적혀
> 있는데, 현재 구조는 셋 다 비공개 구현 세부에 의존한다.
>
> **최종 권고**: 패치 3을 만들지 말 것. SIGTERM + `--resume` + hook 기반
> rewrite 검토.

실제 역사가 하루를 우회해 도달한 결론에, 패치 2 시점에 도달한다.
